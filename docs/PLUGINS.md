# Плагины Studio, API 1

С версии 0.6.0 пакет плагина содержит собственный код Python, ресурсы среды и модуль интерфейса. Он имеет отдельную версию и обновляется без сборки EXE. Один переход на Studio 0.6.0 необходим для установки этого механизма.

В разделе «Плагины» доступны поиск, категории, избранное, быстрый переключатель, настройки, проверка обновлений и откат. «Установить из ZIP» показывает название, версию и разрешения до установки. Сторонний пакет исполняет код с правами приложения; это доверенное расширение, не песочница.

## Файлы и обновления

`plugins/<id>/plugin.json` описывает id, version (три числа), api_version=1, min_app_version, name, description, category, permissions, необязательные backend=`__init__.py` и ui=`ui/entry.js`. При упаковке добавляется список файлов с SHA-256. Пакет ограничен 20 МБ и 500 файлами; ссылки, выход за каталог и повторные имена не принимаются.

Разрешения: `ui`, `theme`, `backend`, `project.read`, `local.model`. Они описывают возможности кода, не обеспечивают изоляцию процесса. Локальную модель и среду большого размера плагин устанавливает отдельно по явному действию пользователя.

Код хранится рядом с БД в `plugin-packages/<id>/<version>-<digest>`, указатель `active.json` хранит текущую и предыдущую установки. Настройки и большие зависимости остаются в `plugins/<id>`: обновление и откат их не удаляют. Встроенный пакет копируется один раз. Новая версия приложения не сбрасывает выбранную версию плагина. Активное задание плагина блокирует его замену; перевод других задач не перезапускается.

Официальные обновления используют отдельные теги `plugin-<id>-v<version>` и GitHub Releases ZIP + SHA256SUMS.txt. Они не меняют latest релиз приложения. Проверка выполняется по кнопке, без фонового опроса сотни плагинов. Установка проверяет совместимость, состав, суммы и загрузку backend до переключения указателя. При сбое остаётся прежний пакет. После успешной установки меняется только модуль этого плагина в окне, без перезапуска Studio.

Сборка: `.venv/Scripts/python.exe tools/package_plugin.py hermes`. Публикация проверенного тега запускает `plugin-release.yml`; EXE не собирается. Для примера темы: `tools/package_plugin.py paper-theme --example`.

## Интерфейс

Модуль экспортирует `create(api)` и возвращает необязательные `configure`, `install`, `stop`, `dispose`. При запуске загружаются только включённые расширения; выключенное загружается по запросу его настроек, без блоков в проекте. Отключение удаляет экземпляр, его элементы, вкладки, стили, подписки и интервалы. Уже запущенная операция агента завершается отдельно; явная кнопка «Остановить» доступна в каталоге.

`api.mount(slot, node)` добавляет собственный узел. Поддерживаются:

- `app.navigation`, `app.footer`, `app.toolbar`, `app.main`, `app.settings`, `app.dialogs`;
- `project.overview`, `project.toolbar`, `project.activity`, `project.errors.actions`;
- `project.settings.translation`, `.context`, `.files`, `.integrations`, `.advanced`.

`api.projectTab(key, title, node)` создаёт отдельную вкладку настроек проекта с управлением клавиатурой. `api.recordActions(factory)` добавляет действие к каждой видимой строке; factory получает строку. Не переопределяйте функции ядра и не перемещайте его поля ввода.

`api.style(css)` при разрешении theme добавляет глобальный CSS: можно менять всё оформление, переменные, размеры и компоновку через селекторы. Отключение удаляет таблицу стилей, возвращая предыдущий каскад. Пример: `examples/plugins/paper-theme`. Несколько тем применяются в порядке загрузки; последняя таблица имеет приоритет при равной специфичности.

`api.lifecycle.register(phase, name, callback)`, `api.listen(target,event,callback,options)`, `api.interval(callback,ms)`, `api.onDispose(callback)` регистрируют автоматически очищаемые ресурсы. Имена обработчиков и вкладок получают пространство имён плагина. Ошибка обработчика плагина изолирована от обновления ядра. Используя собственные ресурсы вне этих методов, плагин обязан освободить их через onDispose.

`api.call(command,...args)` вызывает только таблицу команд backend этого пакета. `api.configure(values)`, `api.setEnabled(bool)`, `api.asset(relativePath)`, `api.project()`, `api.refreshProject()` дают доступ к настройкам, ресурсам и текущему проекту. `api.ui` содержит DOM helpers `element`, `$`, `guard`, `setText`, `toast`, состояние `studioState`, `workspaceUi` и обновление каталога `pluginsUi.refresh`.

Объекты API имеют `version`, `enabled`, `disposed`. Асинхронный код после await проверяет disposed перед изменением состояния. Функции чтения должны ограничивать объём данных и сохранять доказательства/неуверенность. Hermes использует отдельный MCP только текущего проекта, без терминала и записи игры.

## Ядро и совместимость

Автоповтор ошибок, очередь, перевод и сохранение оригинала — часть Studio, доступная без Hermes. Тонкие старые импорты `hermes_*` и методы native bridge оставлены для совместимости интеграций. Производственный загрузчик использует текущую установленную генерацию. Общий API ядра стабилизирован как API 1; если расширению понадобится новая возможность хоста, понадобится версия Studio, предоставляющая её.
