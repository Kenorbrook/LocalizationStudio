# Архитектура

## Структура репозитория

| Каталог | Назначение |
| --- | --- |
| `src/` | Python-модули приложения и обработчика |
| `src/commands/` | Команды, сгруппированные по проектам, строкам, задачам и настройкам |
| `src/storage/` | Транзакционные операции с проектами, строками, задачами и файлами |
| `src/formats/` | Адаптеры извлечения Ren’Py, JSON/JSONL, CSV и TXT |
| `src/ui/` | HTML, CSS и JavaScript встроенного интерфейса |
| `src/translation_tools/` | Отдельно используемый Ren’Py CLI и литературный профиль |
| `tests/` | Автоматические тесты на временных корпусах |
| `packaging/` | Описание сборки приложения, обработчика и установщика обновлений |
| `tools/` | Повторно используемые инструменты разработки и проверки EXE |
| `docs/` | Архитектура, ревью и правила перевода |
| `examples/` | Нейтральные примеры |

`data/`, журналы, резервные копии, модели, игровые тексты и готовые локальные сборки не публикуются. Они не являются исходниками. Их наличие рядом с установленным приложением необходимо для сохранения рабочего состояния.

## Границы модулей

`desktop.py` создаёт окно и сервер. `http_server.py` отвечает за HTTP, защиту localhost, токен и ресурсы. `read_routes.py` связывает маршруты чтения с запросами. `commands/` связывает команды с обработчиками; пользовательские сценарии не импортируют сервер или точку входа.

`queries.py` формирует данные экранов. `core.Store` — совместимый фасад с явной композицией репозиториев `storage/`. Соединения и счётчики принадлежат `Database`; операции с проектами, строками, задачами и файлами имеют отдельных владельцев. Защита ручных правок и история версий находятся в репозитории строк. Атомарная операция остаётся одной транзакцией, в том числе удаление связанных данных проекта. Репозитории не импортируют фасад. Для оценки контекста репозиторий задач получает узкий порт чтения вместо всего приложения. `schema.py` создаёт и обновляет схему; `extraction.py` читает файл и выбирает адаптер из явного реестра `formats/`. Разбор файлов не запускает модель и не обращается к HTTP.

`job_runtime.py` проверяет параметры и запускает обработчик. `job_chain.py` выбирает следующую задачу, `worker.py` исполняет её, `providers.py` обращается к выбранному провайдеру. Планировщик не зависит от `app.py`. Файл `app.py` остаётся совместимой точкой входа CLI и фасадом для существующих импортов.

`providers.py` разделяет недоступность сервиса (`ServiceUnavailable`, очередь на паузу) и неудачное выполнение отдельного локального запроса (`LocalInferenceError`, строка в ошибки, продолжение очереди). Второй случай включает HTTP 500 от `/api/chat` и ошибку Ollama внутри HTTP 200. Для диагностики памяти разбирается только ограниченное тело локального ответа, но оно не переносится в журнал. Ошибки облачных сервисов сохраняют прежнюю обработку.

Запуски из приложения идут прямо в worker без PowerShell, с перенаправлением stdout/stderr в журнал. `worker_supervision.py` следит за завершением процесса и восстанавливает зависшие статусы при чтении состояния и перед продолжением. Идентификатор `worker_launch` отделяет попытки запуска и учитывает различие PID Python venv-запускателя и рабочего процесса; старый наблюдатель не может остановить новую попытку. Восстановление проверяет давность heartbeat и завершение процесса, не прерывает живой обработчик и не запускает перевод автоматически. Очередь и тексты не изменяются. Отдельный Ren’Py CLI сохраняет видимое окно PowerShell.

`paths.py` определяет пути для исходников и упакованного приложения. Единственная настройка пути старого Ren’Py CLI находится здесь; перенос CLI в пакет — отдельная работа.

## Интерфейс

`update_feed.py` читает публичный GitHub Release и сохраняет совместимость с полным ZIP старых релизов. `update_files.py` проверяет защищённый контрольной суммой список `update-files.json`, копирует совпадающие локальные файлы в отдельную сборку и загружает недостающие сжатые файлы по адресам того же релиза. SHA-256 проверяется для сжатого и распакованного содержимого; размер ограничен до и после распаковки. Совпадение определяется содержимым, а не номером версии или датой. Полный ZIP не скачивается скрыто при ошибке списка отдельных файлов. `update_package.py` проверяет конечную сборку, `update_controller.py` сохраняет очереди и передаёт её отдельному установщику, а `update_installer.py` выполняет замену с резервной копией и откатом. Сетевой этап не изменяет файлы работающей программы. В CI все файлы сначала загружаются в черновик релиза и лишь затем релиз публикуется.

`index.html` содержит разметку, `studio.css` — базовые стили, `state.js` — единственный владелец общего состояния проекта, редакторов и страниц; `studio.js` — базовые действия. Локальные DOM-узлы и кэши отрисовки остаются в своих модулях. Модули экрана подключают именованные обработчики через `lifecycle.js`: обновление, дополнение карточек, сбор параметров и навигация. Обработчики вызываются последовательно в порядке регистрации; повторное имя запрещено. Они не подменяют `refresh`, `renderRows`, `settings`, `loadRows` или `showView`.

У загрузки карточек один владелец. Экраны регистрируют описание запроса и действие перелистывания, а общий загрузчик проверяет, что ответ соответствует открытому экрану, сохраняет прокрутку и не меняет активный редактор при фоновом обновлении. На один запрос обновления списка приходится одно чтение списка, а не отдельная проверка версии и повторная загрузка.

`errors_ui.js` владеет разделом ошибок, его постраничным списком и формами повтора. Список находится на экране проекта, а формы используют общий диалог; закрытие диалога не меняет раздел и прокрутку. Неизменившийся список не пересоздаётся при обновлении прогресса.

`workspace_ui.js` собирает рабочую навигацию и окно настроек проекта из существующих контролов, сохраняя их идентичность и обработчики. Параметры проекта, параметры одного запуска и настройки приложения находятся в разных местах. Подсказки доступны по наведению и клавиатуре; пояснения помечаются явно, а ошибки, прогресс и цитаты исходника остаются видимыми. Закрытие настроек отменяет черновик; команда сохранения записывает параметры проекта и отображения истории в одной транзакции. Форматирование прогресса и сводки сохраняет одного владельца в исходном модуле.

Инициализация начинается после `DOMContentLoaded`, когда все модули зарегистрированы. Интернет для ресурсов интерфейса не нужен: они входят в сборку.

Обновления изолированы от переводчика: `update_feed.py` читает GitHub Releases и проверяет скачанный архив; `update_package.py` проверяет разрешённые пути и манифест; `update_installer.py` заменяет файлы с откатом. `update_controller.py` сохраняет очереди и координирует перезапуск через отдельный `LocalizationUpdater.exe`. Native bridge `desktop_api.py` публикует только методы, без объектов контроллеров. Интерфейс обновлений находится в `updates_ui.js`; сетевые действия запускаются явно либо включёнными настройками пользователя.

## Правила изменений

`app_inspection.py` принадлежит экземпляру desktop: снимок выполняет WebView2 через `CapturePreviewAsync`, состояние возвращает фиксированная функция `inspection_ui.js`. `http_server.py` принимает только два аутентифицированных маршрута чтения. `inspection_client.py` обнаруживает сессию по файлу рядом с выбранной базой, проверяет её идентификатор и обращается напрямую к localhost без прокси. Этот клиент используют CLI и stdio MCP; произвольный JavaScript или команды рабочего стола не принимаются. Снимок охватывает viewport веб-интерфейса, включая открытые HTML-диалоги; нативные системные окна в него не входят. Состояние и изображение читаются последовательно, при изменяющемся прогрессе возможна разница в несколько кадров. Ошибка renderer возвращается явно, восстановления или активации окна нет.

- Новый сценарий получает обработчик в подходящем модуле; новый маршрут добавляется в явный реестр.
- Транзакцию изменения связанных данных держать целиком в одном месте. Не дробить атомарные операции ради уменьшения длины файла.
- Общий механизм выделять при наличии реальной повторяющейся ответственности; не добавлять универсальный менеджер для всех экранов и этапов.
- Комментарии объясняют ограничения или причину решения, а не пересказывают действие строки.
- Проверять очереди, конфликты версий, ручную защиту, миграции и офлайн-поведение. Изменения интерфейса дополнительно проверять в EXE на нейтральном корпусе.
- Форматирование Python и UI проверяется в CI. Архитектурные тесты запрещают обратные зависимости и возврат цепочек переопределения четырёх основных функций UI.

## Необязательный агент и восстановление ошибок

`plugin_catalog.py` хранит явный реестр поставляемых плагинов, связывает метаданные с контроллерами и сохраняет избранное приложения в `plugins/catalog.json`. Каталог не сканирует сторонний код и не загружает зависимости при просмотре. Native bridge предоставляет чтение каталога, переключение, избранное и сохранение параметров по ID; неизвестные ID отклоняются. UI `plugins_ui.js` владеет экраном, поиском, фильтрами, категориями и устойчивыми DOM-строками. Отдельные адаптеры регистрируют поддерживаемые действия. После мутации устаревшие ответы фонового чтения не применяются. Для каталогов из 100 записей в EXE используется нейтральная подмена только метаданных; реальных дополнительных плагинов не устанавливается.

`hermes_plugin.py` владеет настройками, фоновыми операциями, дочерними процессами и отчётами Hermes. Немедленный `set_enabled` меняет только разрешение новых запусков, не прерывая процесс. Запуск повторно проверяет разрешение под общей блокировкой. `configure_settings` сохраняет параметры модели под той же локальной блокировкой и не принимает состояние переключателя из устаревшего черновика. `hermes_install.py` проверяет закреплённый установщик, задаёт отдельный HERMES_HOME и очищенное окружение. Ресурсы `plugin_resources` вызывают только необходимые этапы официального bootstrap и PM; автоматическая доустановка продуктов отключена. Данные и среда находятся рядом с БД, вне `_internal` и манифеста обновлений.

`hermes_ui.js` владеет формой параметров агента и действиями в контексте проекта: исследование в файлах/источниках, разбор в ошибках, встроенное восстановление в ошибках и отдельном окне настроек перевода. Последнее явно сохраняется сразу и не входит в черновик общей формы проекта. Модули подключаются через именованные lifecycle hooks, не переопределяя общие функции UI. Экран приложения `plugins` исключён из загрузчика записей и показывает собственную область без панели переводчика; работающие задачи продолжаются независимо от навигации.

Hermes использует локальный OpenAI-совместимый endpoint Ollama. Контекст агента минимум 64 000 токенов и не связан с настройками переводчика. Под общей блокировкой запуска исследование исключает работающие/запускаемые задания; запуск переводчика проверяет признак `hermes_inference`. Установка и проверка метаданных не занимают модель. Обновлятор ждёт завершения любой операции плагина. Остановка затрагивает только отслеживаемое дерево процессов плагина.

Отдельный stdio MCP запускается с `--agent-project ID`. `mcp_server.py` в этом режиме публикует только четыре инструмента `hermes_tools.py` и не допускает вызовы обычного MCP. Инструменты ограничены корнем одного проекта и объёмом чтения; переходы через ссылки/junctions и выход из корня запрещены. Игровые данные считаются недоверенными. Агент не имеет инструментов записи, терминала и общей памяти между играми. Отчёты выводятся как текст.

`error_recovery.py` — независимая от агента политика повторов. План вычисляется из актуальных ошибок, сохраняет ревизии и повторно проверяет их в одной транзакции перед созданием дочерних заданий. Таблицы `recovery_preferences` и `recovery_jobs` хранят согласие проекта и происхождение повторов. Число дополнительных проходов ограничено двумя, партия — 200 строками; повторная постановка одного родителя исключена. Только штатное завершение обработчика с кодом 0 вызывает политику из `worker_supervision.py`, после снятия worker_active. При закрытии приложения, паузе или аварии автоматического продолжения нет. Агент читает обезличенный план числовых параметров, но не управляет очередью.

## Оставшиеся ограничения интерфейса

Модули UI пока подключаются обычными скриптами и используют общие функции интерфейса. Явное состояние и жизненный цикл устраняют скрытые цепочки переопределения, но это не полная миграция на ES-модули. Старый Ren’Py CLI подключается через `paths.py`; его пакетирование остаётся отдельной работой. Поддержка формата извлечения не означает подтверждённую поддержку записи перевода или полного цикла в игровом движке.
