# Localization Studio

Настольное приложение для перевода и проверки игровых текстов на Windows.
Оригинал и перевод рядом, локальная ИИ, ручная редактура, история и возобновляемая очередь — в одном окне.

**Проект находится в стадии alpha.** Это рабочий инструмент для подготовки локализации: качество зависит от модели и контекста, а экспорт необходимо проверить в самой игре.

## Скачать и запустить

1. Откройте [Releases](https://github.com/Kenorbrook/LocalizationStudio/releases) и скачайте архив последней версии для Windows x64.
2. Распакуйте **всю** папку в доступный для записи каталог, например `D:\LocalizationStudio`. Не запускайте EXE внутри архива.
3. Запустите `LocalizationStudio.exe`. Рядом должны оставаться `LocalizationWorker.exe` и `_internal`.
4. Если окно не открывается из-за отсутствия WebView2, установите [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/).
5. Для локального перевода установите [Ollama](https://ollama.com/), загрузите подходящую модель и запустите локальный сервис. Приложение использует `127.0.0.1:11434`.

Готовая сборка не требует отдельной установки Python, Codex или открытия браузера. Модели в архив не входят.
После установки зависимостей и загрузки модели локальный перевод, импорт, поиск, правки и история работают без интернета и VPN.
Интернет нужен для выбранного облачного провайдера, удалённого MCP-клиента и первоначальной загрузки компонентов.

Начиная с 0.4.4 встроенное обновление скачивает только изменённые или отсутствующие файлы. Библиотека Lingua и остальные совпадающие файлы используются повторно после проверки SHA-256; вручную отделять или переносить их не нужно. Окно обновления показывает фактический объём скачивания. Перед установкой создаётся резервная копия, проекты и настройки сохраняются.

Для перехода с 0.4.3 и более ранних версий понадобится один полный ZIP: старый обновлятор ещё не поддерживает загрузку отдельных файлов. После установки 0.4.4 используйте обновления через шестерёнку в приложении. Полный ZIP в Releases остаётся для первой и ручной установки; `update-files.json` и `file-*.gz` приложение обрабатывает само, отдельно скачивать их не нужно.

## Как пользоваться

### Рабочее окно и настройки

Слева находятся текст, очередь, ошибки и папки проверки. Справа — текущая задача, продолжение и лимиты одного запуска. Языки, модель, контекст и правила относятся к проекту и настраиваются кнопкой «Настройки проекта». Облачный API и MCP находятся в «Подключения», технические параметры модели — в «Дополнительно». Поведение окна и обновления относятся к приложению и доступны через шестерёнку внизу.

Пояснения открываются по «?» при наведении, фокусе с клавиатуры или нажатии. В настройках работают «Сохранить изменения», «Отмена» и Escape; закрытие без сохранения возвращает прежние параметры. Лимиты текущего запуска не меняются при сохранении настроек проекта.

### Необязательный плагин Hermes Agent

Откройте «Плагины» внизу левой панели. Это отдельный раздел приложения с поиском по названию и назначению, категориями, избранным и фильтрами установленных, включённых, отключённых и требующих внимания плагинов. Переключатель сохраняет состояние сразу, без открытия формы и кнопки «Сохранить». Поиск, фильтр и прокрутка сохраняются при переходах между экранами.

В строке Hermes Agent нажмите «Установить», затем «Скачать и установить». Среда скачивается отдельно, вместе с собственным Python и зависимостями; модель в эту загрузку не входит. Выберите модель из выпадающего списка установленных моделей Ollama. При необходимости раскройте «Параметры модели» и задайте контекст. Нажмите «Подготовить для Hermes»: приложение создаст отдельный профиль Ollama с этим контекстом, проверит результат и сохранит выбор автоматически. Повторно скачивать веса и вводить команды не требуется. Проверка подключения доступна после подготовки. Затем включите плагин переключателем в каталоге.

Список показывает размер и число параметров, когда Ollama сообщает эти сведения. Если сервис недоступен, показывается причина и кнопка обновления списка; сначала запустите Ollama. Подготовка работает только с уже установленными локальными моделями, поддерживающими инструменты и выбранный контекст. Имена `studio-hermes-*` относятся к отдельным профилям: исходная модель и настройки перевода не изменяются. Повторная подготовка использует ранее проверенный профиль; чужие или изменённые профили не перезаписываются. Подготовка не запускает генерацию и не проверяет, поместится ли модель в память. При отмене или сбое прежняя выбранная модель Hermes сохраняется.

Для установленного плагина кнопка «Настроить» открывает отдельную форму. Редкие параметры контекста находятся в «Параметры модели», журнал — в диагностике. Отключение запрещает новые запуски; уже начатое исследование может завершиться. Для немедленного прекращения есть отдельная кнопка «Остановить».

Hermes требует модель с поддержкой инструментов и контекстом минимум 64 000 токенов; начальная настройка — 65 536. Это отдельный контекст агента, он не меняет параметры перевода. Большой контекст может потребовать значительно больше памяти. Проверка подключения читает сведения Ollama и проверяет среду Hermes, но не загружает модель и не подтверждает, что она поместится в память: это выясняется при первом исследовании.

Во время исследования показываются этап, общее время и число полученных символов. В журнале каждый запуск отделён от установки и предыдущих запросов. Для служебного анализа запрашивается отключение расширенного thinking, а сводка игровых файлов передаётся компактно с количеством пропущенных элементов; при необходимости агент отдельно читает фрагмент файла. Исследование ограничено по числу шагов и общим временем до 30 минут. Большая модель с частичной работой на CPU всё равно может отвечать медленно; «Остановить Hermes» остаётся доступной во время ожидания. При превышении лимита показывается последний этап.

Исследование Hermes находится в «Настройки проекта → Файлы и источники». С обзорного экрана туда ведёт карточка «Файлы и источники». Разбор ошибок доступен непосредственно в разделе «Ошибки». Недоступное действие сопровождается причиной и ссылкой на настройки Hermes. Перед запуском агента приостановите перевод и дождитесь завершения текущего запроса. Hermes получает только четыре инструмента чтения текущего проекта: определение структуры, ограниченное чтение текстовых файлов, ошибки локального перевода и план повторов. Он не получает терминал, браузер, облачные ключи или право изменять игру. Отчёт отделён для каждого проекта; неизвестный архив всё ещё может потребовать отдельного извлекателя. Кнопка остановки завершает только процессы плагина.

В разделе «Ошибки → Автоповтор ошибок» есть встроенная функция Studio, работающая без Hermes. Она также доступна через «Настройки проекта → Перевод → Настроить автоповторы». В отдельном окне переключатель явно сохраняется сразу и относится только к этому проекту. После обычного завершения локального перевода повторяются ошибки памяти и лимитов: уменьшается контекст или число соседних реплик, либо увеличивается резерв ответа. Неизвестные HTTP 500 автоматически не повторяются. Ограничение — до двух дополнительных проходов и до 200 строк из каждого завершённого задания. Уже существующие ошибки можно обработать кнопкой «Запустить подобранные повторы». Включение переключателя само по себе старую задачу не запускает. Пауза, аварийное завершение обработчика, сохранённые оригиналы и ручные правки не возобновляются автоматически.

Среда плагина хранится рядом с базой в `data/plugins/hermes` и сохраняется при обновлении приложения. Загрузка использует закреплённую версию Hermes v0.22.5, проверенный SHA-256 установщика и отдельную папку. Studio не устанавливает Hermes Desktop, gateway, браузерные инструменты и не добавляет плагин в пользовательский PATH. Интернет нужен при установке; исследования используют локальный Ollama напрямую, без VPN и облачного API. Плагин экспериментальный: качество отчёта зависит от выбранной модели.

### Справочник для перевода

Откройте «Настройки проекта → Контекст и персонажи». «Обновить справочник» запускает отдельный анализ импортированного текста. Там же включаются использование справочника и его обновление перед новым переводом. Справочник и неясные места доступны с обзорного экрана проекта. Определение движка и извлечение текста находятся отдельно в «Файлы и источники».

В «Справочник и неясные места» сохраняются персонажи, отношения, термины и сведения о сценах с цитатами и номерами исходных реплик. Уверенные выводы ИИ используются автоматически как предварительные наблюдения. Неясные или противоречивые сведения помечаются «Требует проверки» и не передаются как факты. Их можно исправить и подтвердить, отклонить или оставить вопросом. Подтверждение справочника не меняет статус перевода. Ваши профили персонажей и правила проекта приоритетны.

Приложение подбирает до 12 подходящих сведений по говорящим, упоминаниям в соседних репликах и сцене. Сведения о сцене не переносятся на другие сцены; изменившиеся исходники делают связанные сведения неактуальными. Повторный анализ неизменённых блоков с той же моделью берётся из SQLite-кэша. Анализ и перевод имеют отдельные лимиты запросов. Смена модели или правил создаёт новый проход. Слишком длинная одиночная запись потребует увеличения контекста или предварительного деления документа.

Полная инструкция по регистрации, оплате, доступу из РФ и подключению `venice-uncensored-1-2`: [Venice API](docs/VENICE_SETUP.md).

1. **Откройте проект:** укажите папку игры или корпуса. Приложение анализирует структуру и предлагает поддерживаемые текстовые файлы.
2. **Импортируйте текст:** Ren’Py `.rpy`, JSON / JSONL, CSV или TXT. Можно догружать дополнительные файлы.
3. **Выберите модель и языки:** задайте общий контекст в токенах и число соседних оригинальных фраз. По умолчанию передаётся до 12 фраз до и 8 после, в пределах того же файла и сцены; бюджет модели может сократить контекст.
4. **Начните перевод:** экран процесса показывает очередь и недавнюю историю. В «Настройках нового запуска» можно ограничить новую задачу числом строк или временем. Карточка задачи показывает общий прогресс очереди и отдельно прогресс этого запуска с остатком лимита. На паузе доступны параметры следующего продолжения: новый отсчёт начинается после нажатия «Продолжить». Изменение полей не меняет уже работающий запуск. Ограничение по времени проверяется между строками; текущий запрос сначала завершается, поэтому возможен выход за заданное время. Ошибки входят в число обработанных строк.
5. **Проверьте результат:** локальная редактура, необязательная облачная проверка и ручная правка. Кнопка «Контекст» показывает предыдущие фразы, выбранную строку и последующие записи, а также расположение и говорящего, если они известны.
6. **Экспортируйте отдельный файл** и проверьте его в игре. Приложение не подменяет игровые исходники автоматически.

Для знакомства используйте нейтральный [пример корпуса](examples/dialogue.json): скопируйте его в отдельную папку и откройте эту папку как проект.

## Возможности

- Отдельные проекты со статистикой, списком файлов, поиском и постраничным просмотром.
- Локальный перевод и редактура через Ollama; дополнительный Chat Completions API и MCP.
- Серый статус — без перевода, красный — переведено, жёлтый — после редактуры, зелёный — проверено облачной ИИ или человеком. Статус относится к текущей версии и не гарантирует качество.
- Ручные правки защищены от автоматической перезаписи; доступны история и отмена правки.
- «Брак» и «Ручная проверка» — отдельные пометки и папки внутри проекта. Редактура не снимает их автоматически. Подтверждение человеком снимает пометку, но строка остаётся в открытой папке до выхода. Отмена проверки сохраняет текст и возвращает пометку.
- Ошибка отдельной строки сохраняется, остальные строки обрабатываются дальше. Недоступность провайдера ставит задачу на паузу. Кнопка «Повторить» предлагает очередь с прежними параметрами, очередь с новыми параметрами или ручной перевод вместе с контекстом.
- Повторы запускаются отдельными очередями по порядку после основной задачи; модель и параметры основной задачи не меняются. Список очередей и их параметры видны на экране проекта. Пауза удерживает цепочку; полное закрытие сохраняет её для продолжения.
- Оценка токенов сохраняется с ошибкой и автоматически пересчитывается при изменении параметров повтора. Это приблизительная оценка без вызова модели.
- «Повторить все с новыми параметрами» добавляет все подходящие ошибки выбранного этапа в одну очередь, включая записи за пределами видимой страницы. Повторяющиеся ошибки одной строки не дублируют её в очереди.
- Длинные записи разбиваются на части; готовые части сохраняются. Неразделимые фрагменты и невозможный бюджет запроса выдаются как ошибки, без молчаливого обрезания.
- Символы и паузы сохраняются без вызова модели. Уверенно определённые иноязычные реплики могут сохраняться в оригинале с причиной; короткие слова и имена не считаются надёжным свидетельством другого языка.
- Ручное «Сохранить оригинал» снимает «Ручную проверку» и перемещает строку в «Оригинал без перевода» с причиной. У сохранённой строки также можно явно снять оставшуюся пометку. «Брак» автоматически не снимается.
- В папке «Сохранено без перевода» новые записи появляются сверху. «Перевести» позволяет добавить фразу в конец очереди, обработать следующей после текущего запроса или перевести вручную вместе с контекстом.
- Закрытие окна предлагает трей, полную выгрузку или отмену; выбор можно запомнить. При полной выгрузке перевод остановится, очередь сохранится.
- Завершённые проекты можно скрыть. Удаление проекта из приложения останавливает его обработчик и удаляет относящиеся к нему данные приложения; папка игры не удаляется.

## Поддержка движков и ограничения

Определение движка и безопасное извлечение — разные задачи. Приложение может узнать структуру игры, но не все бинарные архивы и форматы поддерживаются для извлечения и обратной записи.
Текущая версия ориентирована на Ren’Py и уже извлечённые текстовые корпуса. Для неизвестных движков потребуется адаптер или внешний инструмент извлечения.
Автоматический универсальный языковой переключатель в игре не реализован. Субтитры, интерфейс, шрифты и интеграцию перевода нужно проверять отдельно.

### Что ещё не тестировали

**Подтверждённой совместимости с реальными играми пока нет.** Для всех пунктов ниже полный цикл — определение, извлечение, перевод, экспорт и проверка результата в запущенной игре — ещё не проверен. Автоматические тесты и тестовые корпуса не считаются такой проверкой. Это список будущих проверок, а не заявление о поддержке всех перечисленных форматов.

| Движок | Хранение текста для проверки | Статус |
| --- | --- | --- |
| Ren’Py | Открытые сценарии и слой перевода `.rpy`; скомпилированные `.rpyc`; архивы `.rpa` | Не тестировали |
| Unity | TextAsset, сцены и префабы, таблицы локализации, StreamingAssets; `.assets`, AssetBundle / UnityFS, Addressables | Не тестировали |
| Unreal Engine | String Tables, ресурсы локализации `.locres` / `.locmeta`; контейнеры `.pak`, `.utoc` / `.ucas` | Не тестировали |
| Godot | Сценарии и ресурсы `.gd`, `.tscn`, `.tres`; таблицы переводов и `.translation`; пакеты `.pck` | Не тестировали |
| RPG Maker MV / MZ | JSON событий и базы данных, надписи в JavaScript и плагинах | Не тестировали |
| RPG Maker XP / VX / VX Ace | Данные и сценарии RGSS; архивы `.rgssad`, `.rgss2a`, `.rgss3a` | Не тестировали |
| KiriKiri / TVP | Сценарии `.ks`, `.tjs`; архивы `.xp3` | Не тестировали |
| TyranoScript / TyranoBuilder | Сценарии диалогов, конфигурация и плагины | Не тестировали |
| WOLF RPG Editor | Данные событий и базы; упакованные игровые ресурсы | Не тестировали |
| GameMaker | Внешние текстовые ресурсы; строки внутри `data.win` и других контейнеров сборки | Не тестировали |
| Собственный или неизвестный движок | Внешние файлы, собственные архивы, строки в бинарных ресурсах или исполняемых файлах | Не тестировали |

| Каталоги переводов gettext `.po`, `.mo` | Не тестировали |
| Субтитры `.srt`, `.vtt`, `.ass`, `.ssa` | Не тестировали |
| Базы данных, включая SQLite | Не тестировали |
| Текст в открытых игровых сценариях | Не тестировали |
| Скомпилированные сценарии, бинарные ресурсы, архивы, сжатые или зашифрованные данные | Не тестировали |

## Облако и MCP

Облако необязательно. В настройках можно указать адрес совместимого Chat Completions API, модель и свой API-ключ. Ключ хранится в Windows Credential Manager, не в репозитории и не в SQLite.

Пример конфигурации: [mcp_config.example.json](mcp_config.example.json). Замените пути на своё расположение приложения и базы. MCP запускается через `LocalizationWorker.exe --mcp --db <путь>`.

В версии 0.4.1 инструменты `app_ui_state` и `app_screenshot` читают живое окно и получают PNG из WebView2 без управления мышью, клавиатурой или фокусом. CLI: `LocalizationWorker.exe --inspect state` и `LocalizationWorker.exe --inspect screenshot --output <новый файл.png>`. [Описание и ограничения](docs/APP_INSPECTION.md).
Автоматическая генерация через MCP доступна только клиентам с поддержкой `sampling`. Клиенты без sampling могут читать проект и предлагать правки. Имя модели может определяться самим клиентом.
При использовании облака/MCP выбранные тексты и контекст передаются соответствующему провайдеру.

## Данные и обновление

Рядом с приложением создаются `data/studio.sqlite3`, журналы `logs/`, `data/worker-logs/` и кэш `webview-cache/`.
Журналы задач также сохраняются в `translation_tools/studio/` соответствующего проекта.
Внутренний HTTP-сервер слушает только localhost на случайном порту и обслуживает встроенный интерфейс.

Перед обновлением полностью закройте приложение с выгрузкой и сделайте резервную копию `data/`.
Замените EXE и `_internal` из нового архива, сохранив свою базу. Если ранее использовался файл `worker_version.txt`, не оставляйте указатель на старую версию: уберите его либо обновите на новый обработчик.
Не публикуйте `data/`, ключи, серверные токены, журналы и игровые тексты.

## Разработка

Проверено с Windows x64 и Python 3.12. Команды PowerShell из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe src\desktop.py
```

Тесты без реальных запросов к моделям:

```powershell
$env:PYTHONIOENCODING = 'utf-8'
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -p 'test_*.py'
```

После сборки интерфейс EXE можно проверить на отдельном проекте с нейтральными фразами:

```powershell
.\.venv\Scripts\python.exe tools\prepare_feature_test.py
```

Проверка удаляет тестовый проект после закрытия его окна. Итоговый локальный отчёт не публикуется. Скрипт `project_feature_probe.js` предназначен только для этого тестового проекта, поскольку проверяет в том числе удаление проекта.

Временные файлы после работы удаляются; повторно используемые инструменты находятся в `tools`, итоговые локальные отчёты — в `reports`. Резервные копии и кэш переводов сохраняются.

Сборка переносимого приложения:

```powershell
.\build.ps1
```

Результат: `release/LocalizationStudio/`. Распространять всю папку.
На момент первого релиза проходят 135 автоматических тестов; интерфейс собранного EXE дополнительно проверен на нейтральном тестовом корпусе.

Исходники приложения находятся в `src/`, интерфейс — в `src/ui/`, обработчики команд — в `src/commands/`. Тесты вынесены в `tests/`, описание сборки — в `packaging/`, документация — в `docs/`. Подробные границы модулей и оставшиеся ограничения: [архитектура](docs/ARCHITECTURE.md), [ревью кода](docs/CODE_REVIEW.md).

Форматирование проверяется в CI. Локальные команды:

```powershell
.\.venv\Scripts\python.exe -m black --check src tests tools packaging/LocalizationStudio.spec packaging/LocalizationUpdater.spec
.\.venv\Scripts\python.exe tools\format_ui.py --check
```

Для форматирования UI нужен Node.js; первая загрузка закреплённой версии Prettier требует интернета. Он используется только при разработке и не входит в зависимости приложения.

CLI `src/translation_tools/run_translation.ps1` предназначен для отдельно подготовленного Ren’Py слоя `game/tl/russian`. Он открывает видимое окно PowerShell; для обычного приложения используется прогресс внутри окна.

## Обновления приложения

В правой панели откройте «Настройки и проверка → Обновления приложения». Кнопка «Проверить обновления» обращается к публичным GitHub Releases. Новую сборку можно скачать и затем установить с перезапуском.

Отдельно включаются проверка при запуске, автоматическое скачивание и установка, когда нет активных задач и несохранённых правок. По умолчанию все три настройки выключены. Обычная работа с локальной моделью остаётся доступна без интернета.

Перед ручной установкой текущие запросы завершаются, очереди сохраняются; после перезапуска работающие задачи продолжаются с прежними параметрами. MCP-клиенты необходимо отключить перед установкой. Архив и файлы проверяются по SHA-256. База проектов и предыдущие файлы приложения сохраняются в `data/backups/`; пользовательские данные не заменяются файлами релиза. При ошибке замены восстанавливается предыдущая версия.

Обновление из приложения поддерживается начиная с v0.2.0. С v0.1.0 нужно один раз перейти вручную: закрыть приложение, распаковать новую сборку поверх файлов приложения, сохранив папку `data`. Для разработчиков публикация тега `vX.Y.Z`, совпадающего с `src/version.py`, запускает тесты, сборку и создание релиза с архивом и контрольной суммой.
